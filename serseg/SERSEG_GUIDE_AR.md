# دليل لغة SERSEG

هذا الدليل يشرح الميزات الموجودة في هذا المصدر، وليس مواصفات لميزات مستقبلية. رقم المترجم الحالي هو `0.2.0`؛ العمل المطلوب للنسخة 0.5 لم يكتمل. بُنيت التغييرات على لينكس، ونسخة Windows في هذه الحزمة مُجمّعة تقاطعياً فقط ولم تُختبر على جهاز Windows. يلزم اختبارها قبل الاعتماد عليها في عمل مهم.

## 1. تثبيت Windows

تحتاج Windows 10/11 ‏64-bit، وMSYS2 UCRT64 مع GCC. أثناء البناء، يحتاج المترجم `gcc.exe` على PATH. البرامج الناتجة لا تحتاج مترجم SERSEG أثناء التشغيل، لكن لها اعتماديات Windows النظامية؛ لا تفترض استقلالها عن كل المكتبات دون اختبار على جهاز آخر.

1. فك أرشيف المشروع واحفظه، مثلاً في `C:\Houssam\serseg`.
2. إذا لم تكن ثبّت MSYS2 UCRT64 وGCC، اتبع تعليمات MSYS2 الرسمية، ثم من نافذة **MSYS2 UCRT64** ثبّت الحزم اللازمة:

```powershell
pacman -S --needed make mingw-w64-ucrt-x86_64-gcc
```

3. إذا كانت الحزمة تحتوي على `build\serseg.exe` فهي نسخة مبنية تقاطعياً. أو ابنِ المترجم من المصدر في MSYS2 UCRT64: ادخل إلى مجلد المشروع، ثم شغّل `make`. لا تخلط بين طرفية PowerShell وطرفية MSYS2 عند استعمال مسارات مثل `/c/Houssam/serseg`.
4. من PowerShell، ادخل إلى مجلد المشروع وشغّل:

```powershell
cd "C:\Houssam\serseg"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1
```

السكريبت ينسخ المترجم ومكتبة `math` إلى `%LOCALAPPDATA%\Programs\SERSEG`، ويضيف مسار المترجم و`C:\msys64\ucrt64\bin` إلى PATH الخاص بالمستخدم إذا لم يكونا موجودين. إن كان GCC في مكان آخر، استعمل `-GccBin "مسار\bin"`. السكريبت لا يستبدل تثبيتاً موجوداً ولا يحذف ملفاتك. إذا ظهرت رسالة أن المجلد موجود، لا تحذفه عشوائياً: استعمل مجلداً جديداً:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1 -InstallDir "$env:LOCALAPPDATA\Programs\SERSEG-new"
& "$env:LOCALAPPDATA\Programs\SERSEG-new\bin\serseg.exe" --version
```

إذا كانت عندك نسخة قديمة في PATH، يمكن أن ينفذ الأمر `serseg` النسخة القديمة. افحص جميع النسخ:

```powershell
Get-Command serseg.exe -All | Select-Object Source
```

للتجربة في نافذة PowerShell الحالية دون تغيير إعداداتك الدائمة، ضع النسخة الجديدة أولاً:

```powershell
$env:Path = "$env:LOCALAPPDATA\Programs\SERSEG-new\bin;" + $env:Path
serseg --version
```

الإعداد الأخير يخص النافذة الحالية فقط. افتح PowerShell جديداً بعد التثبيت العادي، وجرب `serseg --version` و`serseg help`. `serseg doctor` يعرض الفحوص المتاحة ويُرجع رمزاً غير صفري بسبب النواقص الحالية؛ لا يعتبر فحصاً شاملاً للتثبيت.

لإزالة تثبيت أنشأه السكريبت، شغّل ملف الإزالة الموجود داخله، مثلاً:

```powershell
& "$env:LOCALAPPDATA\Programs\SERSEG-new\uninstall.ps1" -InstallDir "$env:LOCALAPPDATA\Programs\SERSEG-new"
```

يتحقق السكريبت من بصمات الملفات ويسعى لعدم حذف الملفات المعدلة أو غير التابعة للتثبيت. النسخ التي ثُبّتت يدوياً دون `receipt.json` لا يديرها هذا السكريبت.

## 2. أول برنامج

أنشئ ملف `hello.ser` بترميز UTF-8، مثلاً من Notepad:

```text
show "مرحبا من SERSEG"
```

من PowerShell داخل المجلد الذي يحتوي الملف:

```powershell
serseg check .\hello.ser
serseg run .\hello.ser
serseg build .\hello.ser -o hello.exe
.\hello.exe
```

الأوامر أعلاه تتطلب تثبيت المترجم وGCC كما سبق. `build` يرفض الكتابة فوق ملف موجود؛ غيّر اسم الخرج أو احذف بنفسك ملف الخرج الذي تريد إعادة بنائه. من دون `-o` يأخذ الخرج اسم المصدر في المجلد الحالي. `run` يبني برنامجاً مؤقتاً ويشغله. `check` يتحقق من الصياغة والأنواع من دون ربط برنامج نهائي. خيارا التحسين الموجودان هما `-O0` و`-O1` فقط.

## 3. مشروع جديد

```powershell
serseg new my_project
cd my_project
serseg run
```

ينشئ المشروع `src/main.ser` و`serseg.toml` و`README.md`. افتراضياً، `serseg run` يشغّل `src/main.ser`. ملف `serseg.toml` للمعلومات فقط: المترجم لا يقرأه ولا ينزّل حزم منه. لا يوجد حالياً مدير حزم أو `serseg install`.

## 4. قواعد الكتابة

- امتداد المصدر `.ser`، والفصل بين التعليمات يكون بسطر جديد، والكتل داخل `{ }`.
- التعليق يبدأ بـ `#`. أسماء المتغيرات والدوال تستخدم حروفاً إنجليزية وأرقاماً و`_`، ولا تبدأ برقم. الأحرف الكبيرة والصغيرة مختلفة.
- النص بين `"`، ويدعم `\n` و`\r` و`\t` و`\\` و`\"`. العربية داخل النصوص ممكنة؛ أسماء المتغيرات العربية غير مدعومة.
- `let` لا يسمح بإعادة إسناد الاسم؛ `var` يسمح بها؛ `const` يقبل تعبيراً ثابتاً محدوداً. يمكن كتابة نوع صريح بعد `:` أو ترك المترجم يستنتجه.

```text
let name = "سارة"
let age: int = 25
var score = 0
const MAX = 100
score = score + 1
show name
show age
show score
```

الأنواع المدعومة: `int` عدد صحيح 64-bit، و`float` عدد عشري binary64، و`bool` (`true` و`false`)، و`text`. لا يوجد تحويل تلقائي بين `int` و`float`. الأعداد الصحيحة في `+` و`-` و`*` تلتف عند تجاوز 64-bit. القسمة على صفر تنهي البرنامج بخطأ. أعداد `float` تتبع IEEE-754.

## 5. العمليات والشروط

عمليات الحساب: `+ - * /`، والباقي `%` للأعداد الصحيحة. المقارنات `== != < <= > >=` حسب الأنواع المدعومة؛ المنطق `! && ||`؛ والبتات للأعداد الصحيحة `& | ^ ~ << >>`. النصوص تدعم الجمع والمساواة حسب المحتوى. استخدم أقواساً لتوضيح الأولوية.

```text
let age = 20
when age >= 18 {
    show "بالغ"
} otherwise when age >= 13 {
    show "مراهق"
} otherwise {
    show "طفل"
}
show "أهلا " + "بك"
```

## 6. الحلقات

`repeat` يبدأ من الحد الأول وينتهي قبل الحد الثاني، وتُحسب الحدود مرة واحدة. توجد `while` و`each`، و`break` و`continue` داخل الحلقات.

```text
repeat i from 0 to 3 {
    show i
}
var count = 0
while count < 3 {
    count = count + 1
}
```

## 7. الدوال

تُعرّف الدالة على المستوى الأعلى بـ `task`، مع أنواع المعاملات ونوع الخرج، وترجع بـ `give`. يجب أن ترجع كل المسارات قيمة. الدوال المتكررة ممكنة؛ لا تدعم الدوال التقاط المتغيرات الخارجية أو `void`.

```text
task factorial(n: int) -> int {
    when n <= 1 { give 1 }
    give n * factorial(n - 1)
}
show factorial(5)
```

## 8. المصفوفات

توجد مصفوفات ديناميكية من نوع واحد: `int_array`, `float_array`, `bool_array`, `text_array`. الاستدلال يعمل من العناصر؛ المصفوفة الفارغة بلا نوع تصبح `int_array`، ولغيرها أضف نوعاً صريحاً. الفهرسة تبدأ من صفر وتُفحص حدودها.

```text
var names: text_array = []
push names, "أحمد"
push names, "سارة"
names[0] = "علي"
show names.length
show names[0]
each name in names {
    show name
}
```

المصفوفات مراجع مشتركة: إذا نسخت المرجع إلى متغير آخر، التعديل عبر `var` يظهر للمتغيرين. `let` يمنع التعديل مباشرة عبر ذلك الاسم، لا عبر اسم آخر. `each` يحفظ طول المصفوفة عند بداية الحلقة: العناصر المضافة بعدها لا تُزار. المصفوفات المتداخلة والقواميس والمجموعات والتقطيع غير مدعومة حالياً.

## 9. النصوص والإدخال

```text
let name = input("اسمك: ")
show "مرحبا " + name
let value = input("عمرك: ")
when is_int(value) {
    show to_int(value) + 1
} otherwise {
    show "اكتب عدداً صحيحاً"
}
show str(true)
```

`str(x)` يحوّل int أو float أو bool إلى نص. `is_int` و`is_float` يفحصان الإدخال قبل `to_int` و`to_float`؛ التحويل غير الصحيح ينهي البرنامج. `len(t)` و`t.length` يحسبان البايتات؛ `utf8_len(t)` يحسب نقاط Unicode ويتحقق من الترميز. `slice(t, start, end)` يعمل على البايتات، و`utf8_slice` على نقاط Unicode؛ النهاية غير مشمولة. توجد أيضاً `contains`, `starts_with`, `ends_with`, `trim`. العد بنقاط Unicode ليس بالضرورة عدّ الحروف المرئية كاملة.

## 10. الملفات والمكتبة

`use math` يبحث أولاً عن `math.ser` قرب ملف المصدر، ثم عن مكتبة `stdlib` المثبتة قرب المترجم. مثال:

```text
use math
show math.min(3, 7)
show math.max(3, 7)
show math.clamp(12, 0, 10)
show math.min_float(1.5, 2.5)
```

يمكن إنشاء ملف `helper.ser` في مجلد البرنامج يضم تعريفات `task` واستيراده بـ `use helper`، ثم استدعاء `helper.name(...)`. مهام الملفات المستوردة تتشارك نطاق أسماء واحداً؛ تكرار اسم الدالة خطأ. الاستيراد الدوري خطأ. لا توجد خصوصية أو مساحات أسماء معزولة أو مدير حزم. مكتبة الملفات، الشبكات وJSON غير موجودة بعد.

## 11. الاختبارات والذاكرة

`assert condition` ينهي البرنامج بخطأ إذا كان الشرط خاطئاً. `serseg test` يبحث عن ملفات `.ser` داخل مجلد `tests` الحالي ويشغّل كل ملف كبرنامج؛ يفشل إذا لم يجد اختبارات.

النصوص الديناميكية والمصفوفات الحالية تستخدم العدّ المرجعي للإدارة التلقائية، وليس جامع قمامة عاماً. قد تبقى قيمة محلية حتى إعادة استخدام موضعها أو انتهاء الدالة. لا توجد ضمانات سلامة شاملة أو إدارة دورات للكائنات العامة، وهي غير مدعومة أصلاً. راجع `docs/MEMORY.md`.

## 12. VS Code وحل المشاكل

إذا كان ملف `serseg-language.vsix` ضمن الحزمة، يمكن تثبيته عبر أمر VS Code التالي (يتطلب توفر أمر `code` في PATH):

```powershell
code --install-extension .\serseg-language.vsix
```

أو لتثبيت الإضافة من مجلد المشروع:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-vscode.ps1
```

أعد تشغيل VS Code وافتح ملف `.ser`. الإضافة توفر التلوين والمقتطفات، وتشغّل `serseg check` عند الفتح والحفظ، وأوامر **SERSEG: Build current file** و**SERSEG: Run current file** من لوحة الأوامر. قد تكون مواضع التشخيص بعد نص غير ASCII تقريبية. لم تُختبر هذه الإضافة داخل VS Code في هذا البناء، ولا تتضمن LSP أو formatter. إذا وُجد مجلد إضافة قديم يرفض السكريبت استبداله؛ راجعه وأزله يدوياً فقط إن كان يخص SERSEG.

- `serseg` غير معروف: افتح نافذة جديدة وافحص `Get-Command serseg.exe -All` ومسار المستخدم.
- `gcc` غير معروف: ثبّت GCC من MSYS2 UCRT64 وتأكد أن مجلد `bin` موجود في PATH؛ افحص `gcc --version`.
- مجلد التثبيت موجود: استخدم مجلداً جديداً كما في قسم التثبيت؛ لا تحذف محتوياته دون مراجعة.
- لا يمكن العثور على `math`: تحقق من وجود `stdlib\math.ser` بجوار مجلد `bin` في التثبيت، ومن أنك تشغّل النسخة الصحيحة من المترجم.
- المخرجات العربية غير صحيحة: احفظ الملف UTF-8 واستعمل Windows Terminal وخطاً يدعم العربية. سلوك وحدة التحكم على Windows يحتاج اختباراً فعلياً لهذا البناء.

ميزات مثل `fmt` و`clean` ومدير الحزم، الهياكل، `enum`، المكتبة القياسية الواسعة وGC ليست جزءاً من هذا التنفيذ بعد. لا توجد نتائج Windows فعلية أو ضمان أداء عام في هذا الدليل.
