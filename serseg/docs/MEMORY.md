# Memory model for the implemented subset

Immutable `text` and growable `int_array`, `float_array`, `bool_array`, and `text_array` values use automatic reference counting. A text literal is static data; `text + text`, `input()`/`input(prompt)`, and `str()` allocate new text objects. `len`, numeric conversion and validation functions, text search, trim, and slicing consume their temporary owned text arguments; trim and slicing return newly allocated text. Each array literal allocates an array. Expressions produce an owned reference, variable slots own their values, function arguments transfer ownership to the callee, and returned values transfer ownership to the caller. The compiler inserts retains and releases; programmers do not manually free these values. Text objects contain only bytes and arrays contain only scalar values or text, and text does not reference arrays, so these values cannot form reference cycles.

Arrays have shared-reference semantics. An `each` loop retains its iterable for the loop duration (including reassignment of the original variable), snapshots its length, and releases it after completion or when the containing task returns. Mutation through a `var` alias is visible through all aliases, including immutable `let` bindings; `let` prevents direct mutation through that binding, not mutation by other aliases. `push array, value` grows the shared array; indexing checks the signed index and terminates on a bounds error. Nested arrays, array slicing, and concurrent mutation are not implemented. Reading a text element retains it; replacing or dropping an array releases its owned text elements.

Reassignment releases the previous value. Local slots are cleared on first entry; when a declaration is executed again, its old value is released. Remaining local values are released on return from the containing task or on normal program exit. Consequently a value in a block may remain alive after the block exits until the slot is reused or its function returns. `break` and `continue` follow the same rule. Runtime errors terminate the process. Allocation failure and size/reference-count overflow terminate with an error. String concatenation copies its operands and is not optimized for repeated growth.

The generated executable includes the small C runtime; it does not load a separate SERSEG runtime file. Linux x86-64 tests include aliasing, recursion, reassignment, allocation stress, and sanitizer-backed tests. The generated assembly itself is not instrumented by those sanitizer checks. Windows has not been tested.

This is **not** a general garbage collector or a general-purpose object memory model: other heap object types and cycle handling for future reference-containing objects are not implemented. There are no threading or whole-language memory-safety guarantees. Text storage is byte-oriented and is not automatically Unicode-validated; `utf8_len` and `utf8_slice` explicitly validate UTF-8 and operate on code points, not grapheme clusters. Embedded NUL literals are rejected. See `STATUS.md` for other limitations.
