# دليل ويندوز — الحالة الحالية

**لا يتوفر حالياً مُثبّت SERSEG أو ملف `serseg.exe` تم اختباره على ويندوز، ولم تُنشر حزمة إصدار.** لذلك لا توجد خطوات تثبيت مؤكدة أو رابط تنزيل صالح للإصدار حتى الآن. مسار ويندوز في الشيفرة وإعداد CI غير مختبرين، ولا ينبغي اعتبارهما دعماً معتمداً.

## المستودع والتنزيل

المستودع المقصود هو <https://github.com/sersegmd/serseg>. لم تُرفع التغييرات المحلية لأن اتصال GitHub رفض الكتابة. بعد نشر الشيفرة وإنتاج إصدار ويندوز حقيقي واختباره، ستتوفر خطوات تنزيله وتثبيته هنا. لا تحمّل ملفات من مصادر غير موثوقة.

## أوامر اللغة المطبقة حالياً

في نسخة اللينكس المختبرة يمكن إنشاء مشروع بالأوامر الآتية. هذه الأوامر توضح واجهة البرنامج ولا تمثل اختباراً على ويندوز:

```powershell
serseg --version
serseg new my_project
cd my_project
serseg run
serseg check src/main.ser
serseg build src/main.ser
```

ينشئ الأمر ملف `src/main.ser` يحتوي على:

```text
show "Hello from SERSEG!"
```

الأمر `serseg doctor` يعرض الفحوص المتاحة ويعيد حالة فشل حالياً لأن المكتبة القياسية وبيئة إدارة الذاكرة العامة غير منفذتين؛ توجد إدارة محدودة للنصوص ومصفوفات الأعداد الصحيحة فقط. ملف `serseg.toml` المُنشأ للبيانات التعريفية فقط ولا يقرأه المترجم حالياً.

## ما لم يتوفر بعد

- توجد سكريبتات للتثبيت وضبط PATH وإلغاء التثبيت، لكنها لم تُختبر على ويندوز أو في جلسة PowerShell جديدة. لا يوجد مثبت رسومي.
- مدير الحزم وأوامر تثبيت الحزم: غير منفذة.
- توجد إضافة تلوين وsnippets وسكريبت نسخ، لكنها لم تُختبر داخل VS Code. لا يوجد VSIX أو فحص أخطاء.
- إرشادات تشغيل ملف `exe` مستقل وحل مشكلات تثبيت ويندوز: تنتظر إصداراً حقيقياً ونتائج اختبار على ويندوز.

لا تستخدم الإرشادات أعلاه على أنها دليل تثبيت نهائي؛ يجب تحديث هذا الملف بعد بناء إصدار ويندوز والتحقق منه فعلياً.

## بناء تجريبي من المصدر

تم بناء ملف PE للمترجم بأدوات MinGW على نظام آخر، لكن **لم يُشغّل على ويندوز**؛ لا يُعدّ حزمة إصدار أو تثبيتاً متحققاً. لتجربة البناء من المصدر على ويندوز، افتح طرفية MSYS2 UCRT64 وثبّت الأدوات بالأمر التالي، ثم ادخل إلى مجلد `serseg` في المصدر:

```sh
pacman -S --needed make file python mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-python
make test
```

هذه الخطوات وإعداد الاختبارات لم تُنفّذ على ويندوز بعد. يلزم وجود GCC في PATH لبناء برامج SERSEG. لا يوجد مثبّت رسومي أو مدير حزم أو VSIX حالياً.

تتعامل الشيفرة مع BOM في بداية ملف UTF-8 ومع CRLF، وتضيف `.exe` للاسم بلا امتداد، وتحجز 8 MiB للمكدس في ملف PE. عند الإخراج إلى وحدة تحكم يحاول البرنامج استخدام UTF-8 ويسترجع صفحة الرموز عند الخروج؛ صفحة الرموز مشتركة ويمكن أن تتأثر بها برامج أخرى في نفس الطرفية أثناء التشغيل، كما يتوقف ظهور العربية على الخط والطرفية. لم يتم اختبار هذه السلوكيات على ويندوز بعد.

## تجربة سكريبت التثبيت (غير مختبر على ويندوز)

بعد بناء `build/serseg.exe` من مجلد `serseg` في MSYS2 UCRT64، افتح PowerShell في مجلد `serseg` ونفّذ:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1
```

السكريبت يتوقع GCC في `C:\msys64\ucrt64\bin`، ويضيف مسار المترجم وGCC إلى PATH الخاص بالمستخدم إن لم يكونا موجودين. لتغيير مسار GCC استخدم `-GccBin "C:\path\to\bin"`. يرفض استبدال مجلد تثبيت موجود، ويحتفظ بسجل للملفات ومدخلات PATH التي أضافها. إذا فشل أثناء النسخ قد يترك مجلد تثبيت جزئيًا؛ لا يحذف أي ملفات تلقائيًا عند الفشل. افتح PowerShell جديدة وتحقق بـ `serseg --version`. يحتاج المترجم إلى GCC للبناء.

لتثبيت إضافة التلوين وsnippets فقط (بدون diagnostics)، من مجلد المصدر:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-vscode.ps1
```

أعد تشغيل VS Code بعد ذلك. لإزالة تثبيت السكريبت الافتراضي:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Programs\SERSEG\uninstall.ps1"
```

يتحقق السكريبت من بصمات الملفات ويرفض الحذف إن تغيرت، ويحتفظ بالملفات الإضافية ومشاريع المستخدم. يزيل فقط مدخلات PATH المسجلة بأنها أضيفت وقت التثبيت؛ إذا صارت برامج أخرى تعتمد عليها، أعد إضافتها يدويًا. هذه الخطوات لم تُختبر على ويندوز.
